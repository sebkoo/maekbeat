# Roadmap

Maekbeat ships as a sequence of atomic, one-feature commits, C0 through C23. This file is the plan of record; each commit number maps to one reviewable diff on `main`.

## Ordering note

Commits are ordered by dependency, not by calendar, and independent commits may interleave. In particular, C3 (golden tests) and C4 (ARCHITECTURE.md) must never block the runnable-server path to C5; the pipeline itself becomes runnable at C6. The 48–72 hour pace target for reaching C5 binds that runnable path, not the documentation commits.

- C0 — chore: repo bootstrap (this commit — shipped). Config, hooks, CI, and the docs set including this file.

- C11 — feat(web): live vitals chart over WebSocket — shipped [8dfe023](https://github.com/sebkoo/maekbeat/commit/8dfe023): the fan-out leg of docs/ARCHITECTURE.md stage 7 built end to end, since a live dashboard cannot exist without it — an in-process per-device publisher and `GET /devices/:deviceId/stream` in apps/server (frames published after the engine judges them, so no dashboard sees an alert before the frame that raised it; deduped frames never reach it), `streamMessageSchema` + `storedVitalsFrameSchema` added to packages/protocol as the second additive exercise (`v` stays 1), and in apps/web the `subscribe` member the C10 seam was built for: an injectable socket with capped exponential backoff (500 ms doubling to 15 s), four connection states on screen, and a REST back-fill on every re-open instead of a silent resume — bounded, honestly, by the 1000 frames one read can return against the server's 1024-frame ring. Two rules the tests pin rather than the prose: a hole in coverage breaks the line and is shaded, never interpolated across (gaps are found before decimation, so thinning cannot bridge one), and decimation is min/max envelope per bucket, never stride — the suite asserts a one-sample SpO2 trough survives and that a stride sampler over the same series loses it. The x axis is `capturedAtMs` with the consequence stated on the page: a drifting device slides its trace against receive-time alert marks, each anchored to the frame nearest its raise and, if it was raised outside the window the chart holds, not drawn at all but counted. Two small multiples rather than a dual axis, no animation on the newest sample, and apps/web thresholds ratcheted up to 95/91/96/96 against a measured 96.95/92.10/98.19/98.46 — branches measured lower than C10's 93.87% and its threshold therefore held at 91 rather than following it down.
- C12 — feat(web): event timeline + acknowledgement + WCAG 2.2 AA pass — shipped [66e30df](https://github.com/sebkoo/maekbeat/commit/66e30df): acknowledgement as server state, because a metric that dies on reload is not a metric — `POST /devices/:deviceId/alerts/:alertId/decisions` appends to a log that has no update and no delete (apps/server/src/acks.ts), the decision in force is derived by reading the newest event for an alert, and `acknowledged` (seen, acted on) is kept distinct from `dismissed` (seen, judged not actionable) because that difference is the false-alarm signal C23 counts; the schemas land in packages/protocol as the third additive exercise (`v` stays 1) and each decision fans out to every dashboard watching the device. The timeline shows episodes rather than firings — one 30-tick anomaly is one row with a duration, which is what the C7 engine already guarantees and what keeps the C21 alarm-fatigue argument honest — encoded with the docs/DECISIONS.md #12 shape-and-border palette. The WCAG 2.2 AA pass, with its limits named rather than implied: axe-core over three page states with zero violations (structure only — jsdom has no layout, so contrast stays statically gated and target size is asserted as a declaration), keyboard-only acknowledgement, 44x44 controls against the 24x24 minimum, accessible names that start with their visible word, and one polite live region that announces alert transitions and decisions only — a 1 Hz chart inside `aria-live` would interrupt a screen-reader user once a second, so the numbers stay silent and the summary is available on demand (docs/DECISIONS.md #14). docs/demo/preview.gif is captured from the running system by apps/web/scripts/capture-demo.mjs and captioned with its own arithmetic: sampled every 500 ms, played at 10 fps, simulator at 10x, so one GIF second is about fifty simulated device seconds and no latency can be read off it (C23 refreshes it). Capturing it also found a defect no suite could: every test mocked fetch, so nothing had ever crossed an origin, and the dashboard could not actually reach the API from a browser — CORS now ships with the server, allowlist-configurable. apps/web thresholds ratcheted to 96/92/96/97; the loop contract in docs/ai/AI_USAGE.md gains its 2026-08-05 amendment, that every new test is proven against a mutation at writing time.
- C12a — feat(server): keep undecided alerts, count forced evictions — shipped [5ac4510](https://github.com/sebkoo/maekbeat/commit/5ac4510): retention with a judgement in it. The per-device alert history stays bounded, but eviction drops decided alerts before undecided ones (apps/server/src/alerts.ts `evictOne`), because discarding an untriaged alert is the system throwing away exactly what a caregiver has not yet seen. A device whose backlog holds nothing decided still forces a drop — now counted as `forcedEvictions`, served as `alertsForcedEvicted` on GET /devices, and logged at warn, where before it was silent. The decision log outlives the ring: a decision is accepted for an owned, well-formed alertId whose rule, raise ordinal and raise time this engine could have minted — checked by parsing the id rather than by finding the record, so an evicted alert stays decidable for as long as the process lives (malformed id or unknown rule 400; another device's id, or one this device never raised, 404). Those bounds are in-process: a restart resets what "has raised" means, and the server authenticates nobody. The dashboard shows a decision whose alert is gone as its own row rather than hiding it. docs/DECISIONS.md #15 records the choice and docs/regulatory/risk-register.md seeds the hazard it controls for C21. Every guard here was proven against its own mutation and, where a neighbour existed, against that too — recorded in docs/ai/mutation-log.md. Three of those proofs failed to fail: one exposed a counter tested only against zero, one a test whose fixture order hid the bug, and one that the whole feature could be left unwired in buildApp with every server test still green, which is why apps/server/src/retention.integration.test.ts exists.
- C13 — test(web): Playwright smoke against the real system — shipped [18aa597](https://github.com/sebkoo/maekbeat/commit/18aa597), closing Phase 4: five tests, a real Chromium against the production bundle and a real apps/server process, talking across origins. One journey covers load, list, stream over the fan-out socket, alert, acknowledge, and reload — that last step is what proves the decision is server truth rather than component state; one covers the honest-failure path when the API cannot be reached; three re-run the C12 accessibility assertions in an engine that has computed styles, so colour contrast, the focus ring and the 24x24 target box are measured rather than declared. The acceptance requirement was that the gate bites, not that it exists: reverting CORS and unwiring the decision route both fail it, and a production build that cannot load its own assets fails it while every unit suite in the repo stays green — the class that lives between the pieces (docs/ai/mutation-log.md). Retries are zero in CI too, because a smoke test that quietly passes on the second attempt is the same lie as a stale badge; the suite is excluded from the unit coverage ratchet so an end-to-end walk cannot inflate it; and the browser download is cached on its Playwright version. Measured on this machine, the existing gate runs in 8.4 s and the smoke suite adds 10.2 s cold, build included.

## Phase 5 — iOS (complete)

- C14 — feat(ios): SwiftUI scaffold (Swift 5.10+) + SwiftLint + simulator transport — shipped [ec08ac5](https://github.com/sebkoo/maekbeat/commit/ec08ac5): the gating decision came before any Swift, because apps/ios has no package.json and `pnpm -r test:coverage` skips what it cannot see — the exact hole C9 closed for the web, reopening in a new language. A macOS CI job was chosen over a written exemption on a fact worth checking rather than assuming: standard GitHub-hosted runners, macOS included, are free and unmetered for public repositories, and only the larger runners are billed (checked 2026-08-05 against GitHub's Actions billing documentation). So the `ios` job lints with a checksum-pinned SwiftLint 0.65.0 at `--strict`, builds the app target for a simulator, and runs XCTest with `xccov` against an 89% line-coverage threshold set under a measured 91.37% — one number where the vitest packages ratchet four, because xccov reports no branch or function percentage. The C9 guard grew the case it was missing: every non-Node directory under apps/ or packages/ must name the gate that covers it, and a catch-all fails a new one by default. The wire contract crosses languages through the fixtures rather than through a generator — hand-written Codable types whose honesty is checked by decoding the same packages/vitals-sim/golden NDJSON bytes the TypeScript suites pin, asserted field by field on known frames, on the header line's shape, and on each frame's key set round-tripped through the Swift type, which is what stands in for `z.strictObject` where Swift's Codable silently ignores an added field; what the goldens cannot reach is tabulated in apps/ios/README.md rather than implied away. The transport is the fan-out socket the dashboard already uses, with apps/web's reconnect rules and apps/web's numbers, both ports injected so the suite drives a fake socket and a fake clock. The disclaimer is in the interface, empty / loading / error / disconnected are one union, and three source scans keep the app honest: no radio, no store, and the @main shell capped at twenty lines because it is the one file the coverage gate cannot see. Every guard was broken by its own mutation and, where a neighbour existed, by that too; the adversarial pass that closed the commit then broke five more that the first round had not thought of — a CI guard whose grep matched its own text, a second SwiftPM target that shipped code no threshold covered, a Swift file the project compiled from outside the linted paths, a coverage threshold an environment variable could lower, and a disclaimer bar that could be moved inside the navigation stack and disappear on every pushed screen with all 83 tests green (docs/ai/mutation-log.md).
- C15 — feat(ios): CoreBluetooth central + background streaming + BLE state machine — shipped: the hardware honesty problem answered first, because a simulator has no Bluetooth stack and a CI runner has no peripheral, so the untestable surface is a design output rather than an excuse. All the logic lives in a pure state machine with no radio, no clock and no framework import — five phases (disconnected → connecting → connected → streaming → recovering) over nine reachable states, once `hasStreamed` and `wantsLink` were folded into the type — and its whole 9 × 11 transition matrix is asserted, ninety-nine cells — every legal move, every legal no-op, and every illegal one rejected rather than absorbed, because a machine that quietly swallows `notificationsEnabled` on a dead link will one day report streaming with nothing behind it. `recovering` is kept apart from `connecting` by a `hasStreamed` bit: only one of them means a caregiver is missing readings now, the same distinction apps/web fixed at C11. Underneath sits a deliberately stupid CoreBluetooth adapter whose delegate methods translate a callback into an event and do nothing else, held there by a scan for the symbols that would indicate otherwise and a line cap. What CI can still reach is more than "nothing": the six radio-state translations, and a real `CBCentralManager` that constructs and reports `.unsupported` on a simulator; what needs a device is tabulated row by row in apps/ios/README.md alongside the procedure someone with hardware would follow. The GATT profile is docs/ble-gatt-profile.md, and it answers for ATT MTU rather than ignoring it — 23 default, minus 3 for the notification header, leaves 20, and the frame is 19 with one byte spare, so frames are sized to fit and there is no fragmentation layer to get wrong; a vendor UUID rather than borrowing 0x180D for a payload it does not describe. Resume turns the C6 promise into code: the acknowledged mark survives a socket where the in-flight mark does not, a peripheral reboot drops the pre-reboot buffer instead of replaying across it, and the reorder window is 64 because the server's is 64 — the two ends agree about what a reboot is rather than inventing one each. That is checked by launching a real apps/server and reading its own replies, which corrected the documentation twice: the server calls a device's first frame a new session, and an in-window reboot never reaches the server at all, because the gateway's own resume rule drops those frames on the phone — data loss rather than deduplication, now a demonstrated limit rather than a predicted one. Background execution declares bluetooth-central with a restore identifier, and every claim about what iOS then does is labelled permitted, not guaranteed, or unverified; one thing is verified and it is a crash, since CoreBluetooth raises at construction when the identifier is set without the mode, which is why the Info.plist keys are asserted from project.pbxproj. No capability inflation: the app implements a central role against a profile no hardware speaks, and a source scan fails the build on a user-visible string that says otherwise.
- C16 — feat(ios): caregiver notifications — shipped: the circuit closed, server alert to caregiver decision and back into the same append-only log the dashboard writes to, under the same alertId and the same route, differing only in an actor field that reads ios-gateway. The design starts from the bug class rather than from the feature, because it is one the client manufactures on its own: the server guarantees one raise per episode, but a phone that notifies per message notifies again after every reconnect, since a reconnect re-reads the alert history and the fan-out replays transitions — nobody is wrong and the caregiver is buried anyway. So the dedupe is on alertId twice over, in a policy set consulted before scheduling and in the OS notification identifier itself, and C15's invariant carries over unchanged: a banner's owner is the open episode, and resolution or a decision from any client takes it back. Permission is a state rather than an error path, with all five authorization cases rendered and denied loudest, because a monitoring app whose notifications are silently refused is worse than one with none. The wording is held to a banned-word list — the body attributes the alert to a demo threshold rule on synthetic data and never describes a person — and the disclaimer omits "not a diagnosis" rather than exempting itself from its own ban. The untestable surface is drawn tighter than C15's: UNUserNotificationCenter.current() raises in a SwiftPM bundle on macOS and on the simulator alike, so every instance method on the adapter is unexercised by any gate here, which is why the adapter decides nothing and a scan caps it at ninety lines. An integration test against a real apps/server earned its place twice — it found that the engine reports every live episode as ongoing, so keying the notify decision on raised left a cold launch mid-breach silent, a missing banner produced by designing against duplicate ones; and it catches a wrong decision word on the wire that the whole 243-test simulator gate passes through. Local notifications only: no APNs, no device token, no push server, and a source scan fails the build on any of those.
- C17 — test(ios): XCTest unit + snapshot tests — shipped, closing Phase 5: the honest scope was never a count, because the feature commits already ship 243 tests. It was the question this phase kept answering the hard way — what is only ever exercised through an explicitly-injected dependency, so the default path has no caller? Five times a unit suite had proved its own behaviour while nothing proved the composition (C12a's unwired retention, C12's never-crossed origin, C14's `swift test` compiling less than it looked, C16's REST-seed state, C16's default-argument segfault). The enumeration is `DefaultPathTests` and `DefaultValueTests` — the real `URLSession` transport, the real timer and its canceller, both shipped sockets through the clients that build them, the driver's fallback clock, three defaulted handler closures, the inert `#else` ports, the queue's shipped bound, the `ios-gateway` actor, the device screen's production initialiser — and the answer to the same question one level up was the sixth defect and the largest: **`RootView` rendered a `GatewayModel` and never called `start()`**, so the shipped app opened no `/ingest` socket and began no scan, with every gateway test green because each calls `start()` itself. `CompositionTests` catches it, and exists at all because a hosted SwiftUI view does run its `.task` given a key window and an await for the result — which turns C16's two source scans, recorded then as the weaker control they were, into assertions about what happened. The C15 and C16 adversarial findings become permanent seeded suites the way C8 did for apps/server: eight seeds of five hundred random events over the transition table (no illegal state, a rejected event that changes nothing, a backoff sized by the attempt that earned it, and the C15 invariant that no effect outlives its owner), and six seeds of four hundred replay-and-reconnect steps over the notification policy (one episode one banner ever, a closed episode staying closed, every effect accounted for). The first found a violation at seed 1 step 435 — `connecting` is both "trying now" and "waiting out a backoff", and a connect landing in the second left the retry timer running to fire `retryDue` into `connected`, where the machine rejected it and the link screen counted an "unexpected radio event" the radio had not produced, in the one counter whose whole job is to mean the opposite; the second failed first on its own oracle, which replayed `ongoing` for an episode it had already resolved, and the generator was fixed rather than the policy. Five failure paths then run against a real `apps/server` — a dead server at cold launch (`disconnected`, never `empty`), a decision posted into nothing (the banner stays, because withdrawing it would claim a log entry that does not exist), the fan-out socket cut mid-episode and resumed, an alert raised while it was down, and a refused permission — and the fourth found the second defect: `backfill()` re-read frames and not alerts, so an episode that opened during an outage produced no fan-out message and nothing ever asked again, healing the chart across a gap where the alarm did not exist. The coverage ratchet moves for the first time since C14, 89 → 91 under a measured 93.80% (2239/2387, Xcode 26.6, iOS 26.5 simulator), earned rather than chased; apps/ios/README.md gains the file-to-behaviour test map apps/server has had since C8, with a `Runs` column because two files are behind platform guards, and one paragraph naming what is verifiable only on physical hardware. Three defaults are named as having no test rather than omitted — `GatewayModel.live()`, `NotificationCoordinator.live()` and `UserNotificationCenterAdapter()` each raise an ObjC exception a test bundle cannot catch, and the exact messages are recorded from a run.

## Phase 6 — Infra & operations (in progress)

Ordering note: C18 and C19 were swapped during C18. The observability work is provable with an in-memory span exporter and no platform at all, while the container work needs a Docker daemon; putting the provable one first kept the phase moving when neither Docker nor GitHub Actions was available. Nothing shipped was affected, so no commit link changed.

- C18 — feat(server): OpenTelemetry tracing across ingest, alert, and fan-out — shipped (commit link pending the push): instrumentation, not observability — spans exist, no collector is deployed and no backend is stood up, so nothing here makes the running system observable. One trace per ingest message rooted at `ingest.frame` — a rejected or duplicate frame is traced too, since the refusals are half of what an incident is asking about, with `ingest.validate`, `store.ingest`, `alert.evaluate` and `stream.fanout` as its children and one `alert.transition` grandchild per raise or resolve. Every parent is passed explicitly instead of taken from an ambient context, and the proof is a golden NDJSON replay through a real socket asserting the tree by span id (apps/server/src/tracing.shape.test.ts) — because the failure this commit defends against is not the missing span, it is the pile of correctly-named roots that passes every unit test and answers nothing during an incident. Attributes carry identifiers and alert metadata, never a measured value (docs/DECISIONS.md #20). The store now reports whether a frame arrived out of order, which it always knew and used to discard. Off unless `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is set, and off means the provider holds no span processor at all — asserted by asking the provider, with an enabled provider as the positive control, because a `process.getActiveResourcesInfo()` delta proves nothing here: the batch processor `unref()`s its timer, so that list is empty whether tracing is on or off. On `SIGTERM` a spawned server flushes over real OTLP/HTTP to a collector the test stands up, and exits on its own with a client socket still attached. Server coverage ratchets 93/93/93/93 → 95/93/98/95 against a measured 97.05 / 95.00 / 100 / 97.14, earned by moving the shutdown sequence out of the untested process entry into apps/server/src/lifecycle.ts.
- C19 — feat(infra): the system as a deployable, measurable artifact — Dockerfile + compose + CI image build + dashboards-as-code (dashboard definitions checked into infra/), then CDK stacks (S3, Lambda fan-out, ECR, ECS/EC2) with synth-in-CI and a k6 load profile. Measured numbers replace "target" language from here on. This row is phase-sized and lands as more than one commit, the way C12 and C12a did. It has also become the row where the environment finds defects the unit suites could not: containerising the server surfaced a shutdown that ended in SIGKILL, and running it under sustained load surfaced a fan-out buffer with no bound at all. Both are production fixes, both ship here with the test that proves them, because a stage that only packages the software finds nothing.

  - C19, first commit — fix(server): destroy websocket peers that ignore the close frame — shipped locally (no commit link; nothing is pushed): the residual C18 named and left. `app.close()` asks @fastify/websocket to close its clients and does not destroy one that never answers, and `ws` waits thirty seconds before doing it — longer than any container grace period, so the orchestrator's SIGKILL lands first and discards the flush C18 shipped, the shutdown log line and the exit code. The container is what turned a named residual into a measurement: with a raw peer attached, `docker compose stop -t 10` killed the server at 11 s with exit 137. A sweep armed alongside the close — not after it, which is the line an unanswered close frame blocks — terminates whoever is left after one second, at warn, and the polite path keeps its own control. Split out ahead of the image work because a fix that arrives inside a 700-line infrastructure diff is a fix nobody reviews.
  - C19, second commit — feat(infra): container image and compose stack — shipped locally (no commit link; nothing is pushed): the system runs from a container, and the container proves it is this commit. Nine executable proofs rather than nine claims (infra/verify-image.sh, infra/compose-smoke.sh): non-root; a healthcheck observed both green and red, because one never seen failing is a light wired to nothing; the golden `anomaly.ndjson` replayed into the containerised server over a real /ingest socket, with the alert and both fan-out transitions asserted against what the in-process suites expect of the same bytes; the C13 Playwright suite unchanged and pointed at the compose stack by configuration, because a container-shaped copy of those tests would only prove the copy passes; missing configuration failing at startup with the variable named; and no .git, no test file of this repository's and no dev-only dependency in the image. The identity proof is the one the rest hang from: `BUILD_REVISION` becomes both the image's `org.opencontainers.image.revision` and the `revision` field on /healthz, and both are compared to `git rev-parse HEAD` — behaviour is exactly what a stale layer preserves, so a cached image passes every functional assertion while being the wrong software. Architecture is asserted rather than assumed: the host is arm64, the deploy target is not, and `docker build` produces arm64 in silence, so the deploy-target image is built with `--platform linux/amd64`, inspected, and then made to execute and report `process.arch` (docs/DECISIONS.md #22). No reverse proxy, so the browser still crosses an origin to reach the API and the CORS allowlist names the web origin explicitly — a proxy would erase what the C13 smoke exists to prove and leave it green (docs/DECISIONS.md #21). Measured on Colima 0.10.3 rather than Docker Desktop and labelled with it: 305 MB unpacked / 68 MB of layer content for the amd64 server image, 84 / 24 MB for the web image, 20.5 s cold and 11.6 s after a source edit (infra/README.md). Still to come in this row, and not claimed anywhere: the CI image-build job, the compose smoke in CI, any registry publish, dashboards-as-code, the CDK stacks and the k6 profile. Every proof above has run locally and none has run in CI, because GitHub Actions has been in an outage since 15:22 UTC on the day this landed.
  - C19, third commit — test(server): alert and shutdown correctness under sustained load — shipped locally (no commit link; nothing is pushed): three behaviours that a suite driving a handful of frames cannot reach, and two of them had failed before. C18's stop inversion is the reason this exists as a gate rather than a benchmark — a clean stop exited non-zero only once the server had carried enough traffic to buffer spans, so the servers doing their job were the ones failing their stop, and an idle test could not have seen it. It is now pinned twice over: a stop after 300 frames flushes every one of their root spans to a real collector, and a stop whose flush is refused with a 400 still exits 0 and says so at error. Alerts are pinned against drift by a differential — the anomaly fixture replayed while eight other devices stream continuously, its whole fan-out interleaving compared entry for entry against a quiet run, receive-time fields projected out because they are clocks rather than alerts — with the raise anchored to seq 89 and the resolve to seq 152, since a differential is blind to anything that moves both runs equally. Dedupe is driven across six parallel devices, each stream block-shuffled inside the reorder window and every frame sent twice: one accept and one duplicate per frame, every seq readable back, one session epoch each, and exactly one alert episode per device. The harness for spawning a real process and standing up an OTLP collector moved out of src/tracing.lifecycle.test.ts into test-support.ts, since an exit code is only assertable against a real process and a second copy of a racy port-picking retry loop is a copy that drifts. Every guard was broken by its own mutation and left its neighbours green (docs/ai/mutation-log.md); three of them were green while asserting nothing when first written, twice because the "load" never overlapped the thing it was supposed to be loading.
  - C19, fourth commit — fix(server): bound the fan-out send buffer per subscriber — shipped locally (no commit link; nothing is pushed): the gap C11 opened and two commits restated. `socket.send()` queued into the `ws` buffer with no cap and nothing read `bufferedAmount`, which made a dashboard that could not keep up the only client-driven memory growth in a server where the ring buffer, alert history, dedupe set and inbound payload each carry a number. It was deferred on the argument that picking a threshold before measuring one would be inventing it; the load suite that landed first is what produced the measurement — 12.1 MB held against 12.7 MB published over 60 000 frames, 211 bytes per fan-out message, about 18 MB a day per stalled dashboard at 1 Hz. `STREAM_MAX_BUFFERED_BYTES` is 256 KiB, one default ring's worth, on the argument that past a ring's worth behind a subscriber gains nothing by staying attached: a reconnect back-fills the whole ring over REST and anything older is already evicted. The harder half is what happens at the bound, and it is a decision rather than an implementation detail (docs/DECISIONS.md #23): discarding messages and keeping the socket open bounds memory just as well and produces gaps no client is told about, which is apps/web's C11 rule broken from the server side and the exact signature of the C17 defect where the chart healed across an outage the alarm was missing from. So the subscriber is dropped — close code 1013, a warn line, a `slowSubscribersDropped` counter — because both clients already treat any close as reconnect-and-back-fill. Four mutations in docs/ai/mutation-log.md; the one that matters is not a mutation of this diff at all but a plausible optimisation elsewhere, skipping the alert engine when nothing is subscribed, which rebuilds C17's hole and fails on the assertion that an alert raised during the outage is still readable on the reconnect. That assertion caught its own test first: the original version kept a healthy subscriber attached throughout, so the outage it claimed to test never happened.

  - C19, fifth commit — build(infra): resolve the image's pnpm from packageManager — shipped locally (no commit link; nothing is pushed): two items the C19 review left open, and the first one's premise was wrong. The build was recorded as taking whatever pnpm the base image ships; it does not, because `corepack enable` leaves a shim that resolves the version from the nearest manifest whenever pnpm runs, and two mutations failed to displace it — installing pnpm@10.15.0 globally with `--force`, and doing that with `corepack prepare` removed as well (docs/ai/mutation-log.md). The assertion first written to guard it compared pnpm's reported version against `packageManager`, which is corepack's output against corepack's input, and it was deleted rather than kept for appearances. What was genuinely implicit is now explicit: the resolution is done in its own layer before the install, so the dependency on the root manifest already being copied is a stated requirement, the download has its own cache entry, and the build log names the version. The base image is `node:22.22.0-alpine3.22`, now named in docs/ARCHITECTURE.md with the measurement behind leaving it alone — of the arm64 image's 301 MB, about 118 MB is the Node binary and 60 MB the server's production dependencies, so size is a base-image question; dropping the bundled npm the runtime never invokes is a measured 19 MB named as untaken, and distroless would cost three of the nine proofs in infra/verify-image.sh, which shell into the image with `sh`, `id` and `sleep`. Not a reason, and checked rather than assumed: the deployed tree holds no native `.node` addon, and esbuild ships a static Go binary per architecture rather than per libc.
