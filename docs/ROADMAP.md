# Roadmap

Maekbeat ships as a sequence of atomic, one-feature commits, C0 through C23. This file is the plan of record.

## What a row is

One row is one capability: the thing a reader would name if asked what the system gained. **A row that cannot be described in one reader-facing sentence is two rows.**

Most rows are one commit. A row may hold several when one capability arrives in reviewable pieces — C12a and C19 both do — and those commits are listed under it here, because this file is where commit-level detail belongs. The README status board carries one chip per row and never one per commit: a commit link where the row is a single commit, a compare link across the row's range where it is more. `scripts/check-commit-links.sh` enforces both halves.

A row found after the fact takes a letter rather than a number, which is what C12a did: a server capability that came out of writing the web phase, inserted where it belongs instead of renumbering everything after it. C20a is the same shape — a server capability that came out of writing the hazard analysis — and the argument is unchanged: renumbering C21 onward would rewrite three documents to record one insertion.

C19 was authored wider than that rule. A container image, a load rig and an AWS stack are three capabilities, not one, and the nine chips the row grew on the board were the symptom rather than the disease. It is not renumbered — a row is a unit of capability, and renumbering would cascade C20 onward for no gain — but the rule binds every row after it.

## Ordering note

Commits are ordered by dependency, not by calendar, and independent commits may interleave. In particular, C3 (golden tests) and C4 (ARCHITECTURE.md) must never block the runnable-server path to C5; the pipeline itself becomes runnable at C6. The 48–72 hour pace target for reaching C5 binds that runnable path, not the documentation commits.

The timeline shows episodes rather than firings — one 30-tick anomaly is one row with a duration, which is what the C7 engine already guarantees and what keeps the C21 alarm-fatigue argument honest — encoded with the docs/DECISIONS.md #12 shape-and-border palette. - C12a — feat(server): keep undecided alerts, count forced evictions — shipped [5ac4510](https://github.com/sebkoo/maekbeat/commit/5ac4510): retention with a judgement in it. The per-device alert history stays bounded, but eviction drops decided alerts before undecided ones (apps/server/src/alerts.ts `evictOne`), because discarding an untriaged alert is the system throwing away exactly what a caregiver has not yet seen. A device whose backlog holds nothing decided still forces a drop — now counted as `forcedEvictions`, served as `alertsForcedEvicted` on GET /devices, and logged at warn, where before it was silent. The decision log outlives the ring: a decision is accepted for an owned, well-formed alertId whose rule, raise ordinal and raise time this engine could have minted — checked by parsing the id rather than by finding the record, so an evicted alert stays decidable for as long as the process lives (malformed id or unknown rule 400; another device's id, or one this device never raised, 404). Those bounds are in-process: a restart resets what "has raised" means, and the server authenticates nobody. The dashboard shows a decision whose alert is gone as its own row rather than hiding it. docs/DECISIONS.md #15 records the choice and docs/regulatory/risk-register.md seeds the hazard it controls for C21. Every guard here was proven against its own mutation and, where a neighbour existed, against that too — recorded in docs/ai/mutation-log.md. Three of those proofs failed to fail: one exposed a counter tested only against zero, one a test whose fixture order hid the bug, and one that the whole feature could be left unwired in buildApp with every server test still green, which is why apps/server/src/retention.integration.test.ts exists.

## Phase 5 — iOS (complete)

- C14 — feat(ios): SwiftUI scaffold (Swift 5.10+) + SwiftLint + simulator transport — shipped [ec08ac5](https://github.com/sebkoo/maekbeat/commit/ec08ac5): the gating decision came before any Swift, because apps/ios has no package.json and `pnpm -r test:coverage` skips what it cannot see — the exact hole C9 closed for the web, reopening in a new language. A macOS CI job was chosen over a written exemption on a fact worth checking rather than assuming: standard GitHub-hosted runners, macOS included, are free and unmetered for public repositories, and only the larger runners are billed (checked 2026-08-05 against GitHub's Actions billing documentation). So the `ios` job lints with a checksum-pinned SwiftLint 0.65.0 at `--strict`, builds the app target for a simulator, and runs XCTest with `xccov` against an 89% line-coverage threshold set under a measured 91.37% — one number where the vitest packages ratchet four, because xccov reports no branch or function percentage. The C9 guard grew the case it was missing: every non-Node directory under apps/ or packages/ must name the gate that covers it, and a catch-all fails a new one by default. The wire contract crosses languages through the fixtures rather than through a generator — hand-written Codable types whose honesty is checked by decoding the same packages/vitals-sim/golden NDJSON bytes the TypeScript suites pin, asserted field by field on known frames, on the header line's shape, and on each frame's key set round-tripped through the Swift type, which is what stands in for `z.strictObject` where Swift's Codable silently ignores an added field; what the goldens cannot reach is tabulated in apps/ios/README.md rather than implied away. The transport is the fan-out socket the dashboard already uses, with apps/web's reconnect rules and apps/web's numbers, both ports injected so the suite drives a fake socket and a fake clock. The disclaimer is in the interface, empty / loading / error / disconnected are one union, and three source scans keep the app honest: no radio, no store, and the @main shell capped at twenty lines because it is the one file the coverage gate cannot see. Every guard was broken by its own mutation and, where a neighbour existed, by that too; the adversarial pass that closed the commit then broke five more that the first round had not thought of — a CI guard whose grep matched its own text, a second SwiftPM target that shipped code no threshold covered, a Swift file the project compiled from outside the linted paths, a coverage threshold an environment variable could lower, and a disclaimer bar that could be moved inside the navigation stack and disappear on every pushed screen with all 83 tests green (docs/ai/mutation-log.md).
- C15 — feat(ios): CoreBluetooth central + background streaming + BLE state machine — shipped [ad96c2f](https://github.com/sebkoo/maekbeat/commit/ad96c2f): the hardware honesty problem answered first, because a simulator has no Bluetooth stack and a CI runner has no peripheral, so the untestable surface is a design output rather than an excuse. All the logic lives in a pure state machine with no radio, no clock and no framework import — five phases (disconnected → connecting → connected → streaming → recovering) over nine reachable states, once `hasStreamed` and `wantsLink` were folded into the type — and its whole 9 × 11 transition matrix is asserted, ninety-nine cells — every legal move, every legal no-op, and every illegal one rejected rather than absorbed, because a machine that quietly swallows `notificationsEnabled` on a dead link will one day report streaming with nothing behind it. `recovering` is kept apart from `connecting` by a `hasStreamed` bit: only one of them means a caregiver is missing readings now, the same distinction apps/web fixed at C11. Underneath sits a deliberately stupid CoreBluetooth adapter whose delegate methods translate a callback into an event and do nothing else, held there by a scan for the symbols that would indicate otherwise and a line cap. What CI can still reach is more than "nothing": the six radio-state translations, and a real `CBCentralManager` that constructs and reports `.unsupported` on a simulator; what needs a device is tabulated row by row in apps/ios/README.md alongside the procedure someone with hardware would follow. The GATT profile is docs/ble-gatt-profile.md, and it answers for ATT MTU rather than ignoring it — 23 default, minus 3 for the notification header, leaves 20, and the frame is 19 with one byte spare, so frames are sized to fit and there is no fragmentation layer to get wrong; a vendor UUID rather than borrowing 0x180D for a payload it does not describe. Resume turns the C6 promise into code: the acknowledged mark survives a socket where the in-flight mark does not, a peripheral reboot drops the pre-reboot buffer instead of replaying across it, and the reorder window is 64 because the server's is 64 — the two ends agree about what a reboot is rather than inventing one each. That is checked by launching a real apps/server and reading its own replies, which corrected the documentation twice: the server calls a device's first frame a new session, and an in-window reboot never reaches the server at all, because the gateway's own resume rule drops those frames on the phone — data loss rather than deduplication, now a demonstrated limit rather than a predicted one. Background execution declares bluetooth-central with a restore identifier, and every claim about what iOS then does is labelled permitted, not guaranteed, or unverified; one thing is verified and it is a crash, since CoreBluetooth raises at construction when the identifier is set without the mode, which is why the Info.plist keys are asserted from project.pbxproj. No capability inflation: the app implements a central role against a profile no hardware speaks, and a source scan fails the build on a user-visible string that says otherwise.
- C16 — feat(ios): caregiver notifications — shipped [dfb105a](https://github.com/sebkoo/maekbeat/commit/dfb105a): the circuit closed, server alert to caregiver decision and back into the same append-only log the dashboard writes to, under the same alertId and the same route, differing only in an actor field that reads ios-gateway. The design starts from the bug class rather than from the feature, because it is one the client manufactures on its own: the server guarantees one raise per episode, but a phone that notifies per message notifies again after every reconnect, since a reconnect re-reads the alert history and the fan-out replays transitions — nobody is wrong and the caregiver is buried anyway. So the dedupe is on alertId twice over, in a policy set consulted before scheduling and in the OS notification identifier itself, and C15's invariant carries over unchanged: a banner's owner is the open episode, and resolution or a decision from any client takes it back. Permission is a state rather than an error path, with all five authorization cases rendered and denied loudest, because a monitoring app whose notifications are silently refused is worse than one with none. The wording is held to a banned-word list — the body attributes the alert to a demo threshold rule on synthetic data and never describes a person — and the disclaimer omits "not a diagnosis" rather than exempting itself from its own ban. The untestable surface is drawn tighter than C15's: UNUserNotificationCenter.current() raises in a SwiftPM bundle on macOS and on the simulator alike, so every instance method on the adapter is unexercised by any gate here, which is why the adapter decides nothing and a scan caps it at ninety lines. An integration test against a real apps/server earned its place twice — it found that the engine reports every live episode as ongoing, so keying the notify decision on raised left a cold launch mid-breach silent, a missing banner produced by designing against duplicate ones; and it catches a wrong decision word on the wire that the whole 243-test simulator gate passes through. Local notifications only: no APNs, no device token, no push server, and a source scan fails the build on any of those.
- C17 — test(ios): XCTest unit + snapshot tests — shipped [cbf37d2](https://github.com/sebkoo/maekbeat/commit/cbf37d2), closing Phase 5: the honest scope was never a count, because the feature commits already ship 243 tests. It was the question this phase kept answering the hard way — what is only ever exercised through an explicitly-injected dependency, so the default path has no caller? Five times a unit suite had proved its own behaviour while nothing proved the composition (C12a's unwired retention, C12's never-crossed origin, C14's `swift test` compiling less than it looked, C16's REST-seed state, C16's default-argument segfault). The enumeration is `DefaultPathTests` and `DefaultValueTests` — the real `URLSession` transport, the real timer and its canceller, both shipped sockets through the clients that build them, the driver's fallback clock, three defaulted handler closures, the inert `#else` ports, the queue's shipped bound, the `ios-gateway` actor, the device screen's production initialiser — and the answer to the same question one level up was the sixth defect and the largest: **`RootView` rendered a `GatewayModel` and never called `start()`**, so the shipped app opened no `/ingest` socket and began no scan, with every gateway test green because each calls `start()` itself. `CompositionTests` catches it, and exists at all because a hosted SwiftUI view does run its `.task` given a key window and an await for the result — which turns C16's two source scans, recorded then as the weaker control they were, into assertions about what happened. The C15 and C16 adversarial findings become permanent seeded suites the way C8 did for apps/server: eight seeds of five hundred random events over the transition table (no illegal state, a rejected event that changes nothing, a backoff sized by the attempt that earned it, and the C15 invariant that no effect outlives its owner), and six seeds of four hundred replay-and-reconnect steps over the notification policy (one episode one banner ever, a closed episode staying closed, every effect accounted for). The first found a violation at seed 1 step 435 — `connecting` is both "trying now" and "waiting out a backoff", and a connect landing in the second left the retry timer running to fire `retryDue` into `connected`, where the machine rejected it and the link screen counted an "unexpected radio event" the radio had not produced, in the one counter whose whole job is to mean the opposite; the second failed first on its own oracle, which replayed `ongoing` for an episode it had already resolved, and the generator was fixed rather than the policy. Five failure paths then run against a real `apps/server` — a dead server at cold launch (`disconnected`, never `empty`), a decision posted into nothing (the banner stays, because withdrawing it would claim a log entry that does not exist), the fan-out socket cut mid-episode and resumed, an alert raised while it was down, and a refused permission — and the fourth found the second defect: `backfill()` re-read frames and not alerts, so an episode that opened during an outage produced no fan-out message and nothing ever asked again, healing the chart across a gap where the alarm did not exist. The coverage ratchet moves for the first time since C14, 89 → 91 under a measured 93.80% (2239/2387, Xcode 26.6, iOS 26.5 simulator), earned rather than chased; apps/ios/README.md gains the file-to-behaviour test map apps/server has had since C8, with a `Runs` column because two files are behind platform guards, and one paragraph naming what is verifiable only on physical hardware. Three defaults are named as having no test rather than omitted — `GatewayModel.live()`, `NotificationCoordinator.live()` and `UserNotificationCenterAdapter()` each raise an ObjC exception a test bundle cannot catch, and the exact messages are recorded from a run.

## Phase 6 — Infra & operations (in progress)

Ordering note: C18 and C19 were swapped during C18. The observability work is provable with an in-memory span exporter and no platform at all, while the container work needs a Docker daemon; putting the provable one first kept the phase moving when neither Docker nor GitHub Actions was available. Nothing shipped was affected, so no commit link changed.

- C18 — feat(server): OpenTelemetry tracing across ingest, alert, and fan-out — shipped [3260723](https://github.com/sebkoo/maekbeat/commit/3260723): instrumentation, not observability — spans exist, no collector is deployed and no backend is stood up, so nothing here makes the running system observable. One trace per ingest message rooted at `ingest.frame` — a rejected or duplicate frame is traced too, since the refusals are half of what an incident is asking about, with `ingest.validate`, `store.ingest`, `alert.evaluate` and `stream.fanout` as its children and one `alert.transition` grandchild per raise or resolve. Every parent is passed explicitly instead of taken from an ambient context, and the proof is a golden NDJSON replay through a real socket asserting the tree by span id (apps/server/src/tracing.shape.test.ts) — because the failure this commit defends against is not the missing span, it is the pile of correctly-named roots that passes every unit test and answers nothing during an incident. Attributes carry identifiers and alert metadata, never a measured value (docs/DECISIONS.md #20). The store now reports whether a frame arrived out of order, which it always knew and used to discard. Off unless `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is set, and off means the provider holds no span processor at all — asserted by asking the provider, with an enabled provider as the positive control, because a `process.getActiveResourcesInfo()` delta proves nothing here: the batch processor `unref()`s its timer, so that list is empty whether tracing is on or off. On `SIGTERM` a spawned server flushes over real OTLP/HTTP to a collector the test stands up, and exits on its own with a client socket still attached. Server coverage ratchets 93/93/93/93 → 95/93/98/95 against a measured 97.05 / 95.00 / 100 / 97.14, earned by moving the shutdown sequence out of the untested process entry into apps/server/src/lifecycle.ts.
- C19 — feat(infra): the system as a deployable, measurable artifact — Dockerfile + compose + CI image build + dashboards-as-code (dashboard definitions checked into infra/), then CDK stacks (S3, Lambda fan-out, ECR, ECS/EC2) with synth-in-CI and a k6 load profile. Measured numbers replace "target" language from here on. This row is phase-sized and lands as more than one commit, the way C12 and C12a did. It has also become the row where the environment finds defects the unit suites could not: containerising the server surfaced a shutdown that ended in SIGKILL, and running it under sustained load surfaced a fan-out buffer with no bound at all. ## Post-release track (no commit numbers)

Growth here means trust signals, not star counts. The targets are README conversion (a visitor understands and believes the repo in under a minute), a current demo GIF, answered issues, and small honest commits.

Launch distribution follows each channel's norms: Show HN on a Tuesday–Thursday morning ET without vote soliciting, stack subreddits per each sub's rules, a dev.to build-log series, and awesome-list PRs after the 30-day rule.

Product explorations, in no fixed order:

- ASO sheet for a future App Store listing.
- StoreKit 2 IAP exploration: premium reports, caregiver circles.
- GitHub Sponsors.
- AGENTS.md, CODE_OF_CONDUCT, and an OpenSSF Scorecard run.

Monetization follows a real free core; it never precedes it. Any consumer-facing release with real caregivers would need a regulated posture that this educational repo (see DISCLAIMER.md) does not claim; until then these explorations stay design exercises.
